# Level 3: Act した後の状態変化を確認する

## これから何をするか

戻り値ではなく、Act の実行によってオブジェクトの「状態」がどう変わったかを検証します。

## なぜそうするか

戻り値を持たないメソッド(`void` を返すメソッドなど)は、状態の変化そのものを確認しないとテストにすることが難しいです。

## 進め方

1. `ShoppingCartServiceTests.cs` を開く。最初の1本は見本として完成している
2. 次にやる `[Fact(Skip = "...")]` を1つ選び、Skip を外す
3. 「このテストで何を確かめたいか」を先に言葉にしてから、Arrange / Act / Assert を書く
4. `dotnet test` で緑になったら、次の1本へ

## 書くときの約束

- 3A(Arrange-Act-Assert)のコメントは目印として置いてある。消さずに、その下に中身を書く。どこまでが準備で、どこからが検証かが読み手に伝わる
- 期待値に計算式を書かない。`Assert.Equal(100m * 3, cart.TotalAmount)` と書くと、プロダクションコードと同じ間違いをテストも犯してしまう。`Assert.Equal(300m, ...)` と値を直接書く
- 1つのテストで確かめることは1つにする

## サンプルコード

```csharp
[Fact]
public void Increment_呼び出すと_Countが1増える()
{
    // Arrange
    var counter = new Counter();

    // Act
    counter.Increment();

    // Assert
    Assert.Equal(1, counter.Count);
}
```

## 発展課題

ここから先は、テストメソッド名も用意されていません。以下の要件について、まず「どうあるべきか」を決めてからテストを書いてください。

1. 同じ商品名を2回追加したら、カートの中身はどうなるべきか(1件にまとまる? 2件のまま?)
2. カートに入っていない商品名を削除しようとしたら、どうなるべきか
3. 何も入っていないカートの `TotalAmount` はいくつか

話し合ったら、実際に `ShoppingCartService` がどう振る舞うかをテストで確かめてください。

先に決めた「あるべき姿」と、実際の振る舞いが食い違うことがあります。 そのときは、それが仕様なのかバグなのかを判断してください。この教材ではプロダクションコードは変更しないので、「現状の振る舞いをテストで固定した上で、コメントに疑問を書き残す」という形で構いません。実務でも、既存コードにテストを足すときはこの順序になります。
